01 · Timeline

Eight shifts, each one a bottleneck removed.

Pick an era. Every card follows the same format: what was broken, what fixed it, what that unlocked, and what changed in compute, data and code.

Prelude · before 2017, in one line each
1972 · TF-IDF

Bag of words

Counts words in sparse vectors with no order and no meaning. "Dog bites man" equals "man bites dog".

2013 · Mikolov et al.

Word2Vec / GloVe

Dense vectors where similar words sit close together. But each word gets one vector, whatever its context.

1986 / 1997 → 2014

RNN · LSTM · GRU

Read tokens in order and carry a hidden state. Gates help with vanishing gradients, but the loop is serial.

2014 – 2015

Seq2Seq + attention

Bahdanau and Luong let the decoder look back at every encoder state, though still on top of RNNs.

03 · The equation

Scaled dot-product attention, one term at a time.

Hover over or tap any part of the formula. Shapes use the PyTorch convention: B batch, H heads, T tokens, d_k head dimension.

Attention(Q,K,V)= softmax ( QKT dk +M ) V
Why divide by √dk?

Without scaling, softmax becomes almost one-hot.

One query against 8 random keys. Dot products of dk-dimensional random vectors have variance ≈ dk. Drag the slider and watch the unscaled weights collapse onto a single key, which leaves almost no gradient for the others.

04 · Playground

Type a sentence and watch it attend.

Each row is a query token and each column a key it can look at. Rows sum to 1. Click a row to see what that token attends to. Turn off the causal mask to switch from GPT-style to BERT-style.

Attention heads

These heads use synthetic weights so the page runs offline. Each one reproduces a pattern researchers have found in trained models: previous-token heads (part of induction circuits, Olsson et al. 2022), attention sinks on the first token (Xiao et al. 2023), and content matching.

05 · Efficiency labs

The numbers behind serving and tuning at scale.

The KV cache, Mixture of Experts and LoRA are the three ideas you will meet in every model card, inference server and fine-tuning budget. The presets use the real published configurations.

KV cache memory

Every generated token stores a key and a value vector, per layer and per KV head. Grouped-query attention cuts the number of KV heads.

Decode step by step. The prompt is prefilled once, then each new token adds one K/V column.

Top-k routing

A router scores every expert for each token, keeps the top k, and mixes their outputs by the renormalised gate weights.

Routing here is simulated with a seeded hash. The Mixtral paper found experts specialise more by syntax and token type than by topic.

06 · Diagrams

How data flows, with tensor shapes.

The Mermaid source for all four diagrams is in diagrams.md, alongside the code files.

Inference: prefill, then decode with a KV cache

Prefill is compute-bound. Decode is memory-bound, because each step reads the whole cache.

flowchart LR
  P["Prompt tokens (B, T)"] --> PF["Prefill: one parallel forward pass"]
  PF --> C[("KV cache per layer: (B, KV, T, d_k)")]
  PF --> L1["Logits for last token"]
  L1 --> S["Sample next token"]
  S --> D["Decode step: (B, 1)"]
  D --> Q["Compute q, k, v for 1 token"]
  Q --> A["Attend q over cached K, V"]
  C --> A
  Q -->|append k, v| C
  A --> S

Sparse Mixture of Experts layer

This replaces the dense MLP. Only k experts run for each token.

flowchart TD
  X["Token hidden state x (d_model)"] --> R["Router: softmax(x W_r) over E experts"]
  R --> K["Keep top-k, renormalise gates"]
  K --> E1["Expert i: SwiGLU MLP"]
  K --> E2["Expert j: SwiGLU MLP"]
  X --> SH["Shared expert (DeepSeek)"]
  E1 --> M["Weighted sum g_i E_i(x) + g_j E_j(x)"]
  E2 --> M
  SH --> M
  M --> Y["Output (d_model)"]
  R -.-> LB["Load-balancing loss E * sum f_i P_i"]

Agent loop with tools

This is ReAct-style. MCP standardises the tools box.

flowchart TD
  G["Goal + system prompt + tool schemas"] --> LLM["LLM decides"]
  LLM -->|tool_call JSON| T["Run tool (search, code, API, MCP server)"]
  T -->|observation| MEM["Append to messages / state"]
  MEM --> LLM
  LLM -->|final answer| OUT["Return to user"]
  MEM -.-> CAP{"Step limit or budget hit?"}
  CAP -->|yes| OUT
07 · Agents

Every agent framework is this loop.

This replays the actual output of 06_agent_loop.py: retrieve, calculate, answer. LangGraph, the Claude Agent SDK and the OpenAI Agents SDK add state, retries and parallel branches around the same core.

1
Model reads goal + tool schemasTools are described as JSON Schema. With MCP, a server publishes them.
2
Model emits a tool call{"tool": "search_docs", "args": {...}}. Structured output, not prose.
3
Your code runs the toolThe model never executes anything. The loop does, so this is where permissions live.
4
Observation goes back into contextRepeat until the model answers or a step cap stops the loop.
